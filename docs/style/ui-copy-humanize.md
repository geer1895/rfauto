## 0. 适用边界（先分档，再套规则）

| 文案形态 | 例子 | 适用规则 |
|---|---|---|
| 超短文案 | 按钮、标签、表头、toast 主题 | R1/R2/R6/R9/R14（词汇与守恒类）；句长节奏类**不适用** |
| 段落文案 | help 块、引导文、空态说明、错误详情 | 全套适用（含 R4/R5/R11/R12/R13/R17） |
| 不适用面 | 表格列头、枚举值、单位、`{name}` 占位符、频段/dB 数值 | 格式要求不是 AI 味，一律不动 |

三条元纪律（护栏，违反即回滚）：

1. **命中 ≠ 必改**：只处理规则命中处；未命中句子逐字保留，不顺手润色。
2. **信息守恒**：改写零信息损失——键名、命令、文件名、单位、阈值、
   数字、`{placeholder}`、限定语（"约 30 秒"式事实限定）一个不动；
   换不出的空话**删掉**而不是换同族空话（删"一目了然"不能补"清晰直观"）。
3. **先删、再具体化、再降格式**：优先级从左到右；写不出具体细节补位
   的，删。

## 一、词汇层

### R1 均值回归测试（最高优先级）

判据：把文案里的产品名抽掉，放到任何一个 EDA/仿真/数据工具上都成立
→ 塞回 rfauto 专属细节（页面名、命令、文件名、数据名词）。

- 反例 `common.error_generic`：**操作未成功（服务未就绪或请求异常），
  可稍后重试**——任何 Web 应用都能用这句；"可稍后重试"是"请稍后再试"
  家族（见 R8）。
- 正例 `dashboard.cred_load_fail`：**锚注册表加载失败，可信度数字暂不
  可用**——点名了哪个资产（锚注册表）、影响什么（可信度数字），只可能
  属于本工具。
- 自查：写完一句说明，遮住页面名问"这是哪个软件？"认不出就重写。

### R2 套话黑名单（zh，零容忍逐词检索）

值得注意的是、标志着、彰显、凸显、奠定了基础、助力、赋能、抓手、
闭环（物理"闭环环带"义豁免，如 `gallery.desc_ring_resonator`）、
一站式、全方位、多维度、轻松、轻松搞定、强大的、智能的、完美、
一目了然、清晰直观、深耕、海量、丰富多彩、保驾护航、致力于、旨在、
卓越、极致、无缝。

- 反例 `timeline.help_1`：**——调参/战役是否在进步一目了然**——删掉
  "一目了然"句意不损失（R3 一并处理）。
- 改法：删词后句意不变就删；句意塌了说明底下没东西，塞事实（R1），
  不是换词。

### R3 清嗓句与空洞分析尾删除

判据：尾巴句删掉后不缺信息 → 整句删。"，帮助你……""，让你轻松……"
"，从此……""，尽情……"式尾巴同族。

- 反例 `timeline.help_1` 尾段"**——调参/战役是否在进步一目了然**"：
  预测读者反应（"你会看得清楚"）不是信息；图怎么读（线走低=进步）
  才是信息。
- 正例 `tune.help_flow`：**这页自动寻找更好的参数：每一轮（trial）按
  一组参数值仿真一次并打分，跑完后给出评分最好的那组参数。**——全程
  事实，零尾巴。
- en 侧同族："— progress at a glance" / "helps you…" / "lets you…"

### R6 数字与专有名词守恒（改写红线）

判据：改写零信息损失——以下七类**逐字不动**，改写前先圈出来（锁保护
清单）：①命令与代码（`optstack.src_hint` 的 "tune --multi（nsga2）"）；
②文件名/路径（`guide.wf1_out` 的 "recipes/ 下一个 YAML 文件"）；③数字
与版本（`foot.version_note` 的 "2025 R1 / v251"、`import.ver_default`
的 "2025.1"）；④单位与量纲（`fieldviz.sar_note_lead` 的 "1g 平均"）；
⑤`{placeholder}` 占位符（`dashboard.aria_move_tpl` 的 "{name}，位次
{pos}/{total}"）；⑥阈值与默认值（`dashboard.trend_empty` 的 "至少 2
个"）；⑦术语固定译法（trial/run/recipe/锚 不换同义词）。改写后逐类
回读（R18 清单第 1 条），动了任何一类即回滚。

### R14 营销称呼腔禁用

判据：文案在"对用户表演亲切"而不是"对用户说事"。禁："…的你、懂你、
贴心、小助手、亲、么么哒"式称呼；感叹号默认不用（错误/警告文案禁）。

- 反例 `guide.subtitle`：**写给第一次接触 rfauto 的你**。
- 改向：直接说给谁、干什么——"从零开始：跟着内置示例走通第一条链路"
  （信息只增不减：保留了"第一次/内置示例"语义）。

## 二、句式层（段落文案适用；超短文案跳过）

### R4 对仗与三连限额

判据：同一串里 ≥3 个 ≤10 字的连续逗号段，且每段没有专属信息（可互换
顺序、删一两段不缺信息）→ 收敛到有内容的一两项。**具体枚举放行**
（误杀边界：每项都是真实存在的独立对象/键位/字段，删了就丢信息）。

- 放行 `palette.placeholder`：**跳转页面、# 搜 run、> 命令…**——三个
  前缀键位是真实操作语法，删哪个都丢功能说明。
- 放行 `runs.help_1`：**S 参数曲线（可切分量）、3D 模型、产物、配方
  快照**——四个真实产物名。
- 拦截形态（仓内暂无实例，2026-10-23 扫描零命中）："更快、更好、更稳"
  式空洞三连——新增文案时按判据拦，不许入库。

### R5 "不是 A 而是 B" 限额

判据（短文案版）：整页 ≤1 次；且删掉句型后前后两半必须说了**不同的
东西**——两半同义即整句删。变体"并非…而是…""不仅…更…"同族处理。
仓内存量：零命中（2026-10-23 扫描）；本条为新增拦截用。
正常对比写法参照 `guide.wf3_a`：**因为 fake 是解析近似模型，不是真实
电磁仿真**——后半句是实质区别（曲线由闭式公式生成），不是修辞性反转。

### R11 句长与节奏（help 块/引导文）

判据：中文单句 ≤60 字；一句只说一件事；连续三句等长必打断一句。
括号补充说明 ≤1 层（`timeline.help_1` 一句塞了"按配方目标重算，越低
越好"+两个括号注=一句三事，拆开）。

- 正例 `import.msg_hint`：**首次启动 AEDT 需约 30 秒；读取前请确认工程
  未被其它 AEDT 窗口占用（残留 .lock 会导致失败）。**——两句两事，
  括号只装一个因果。

### R12 系动词回避与名词化空转

判据："进行 X 操作"→ 直接写动词"X"；"实现了…的提升"→ 写提升了多少。
仓内存量：零命中（"进行中"是状态徽标、"进行中的仿真"是真实动宾，
均不算）。本条为新增拦截用。

### R13 限缩语与安全垫

判据：同句限定词 ≤1 层；事实型限定（"约 30 秒""至少 2 个带指标的
run"）一个不能删——它们是可信度来源；姿态型（"可能、或许、一定程度
上"叠加）合并成一个。

- 正例 `dashboard.trend_empty`：**数据不足（至少 2 个带指标的 run）**——
  限定是可执行的验收条件，不是安全垫。

### R17 标点与格式

中文全角标点（英文短语/URL/代码例外）；破折号每段 ≤1 次；粗体每段
2-3 处封顶；「」引用 UI 元素名（本仓惯例，照 `guide.wf1_li1`"点卡片
「详情」"）。

## 三、功能文类（空态/错误/按钮/help）

### R7 空态文案三档

判据：E1（有下一步指引：指到能产生数据的页面/命令）> E2（说明成因或
出现条件）> E3（裸状态，禁用于页面级空态）。表格/下拉单元占位（"无"
"（无报告）"）豁免——语境自明，硬塞指引是噪音。

- E1 正例 `dashboard.activity_empty`：**暂无活动——去「工程导入」跑
  第一个 run**。
- E1 正例 `runs.empty_no_runs`：**还没有仿真记录。到「优化调参」页跑
  一轮，或用命令行先来一发：**（页面名+动作+备选路径三件套）。
- E2 正例 `loopboard.no_boards`：**（暂无看板——跑自治环后出现）**。
- E3 反例 `optstack.empty_no_front`：**该 run 暂无可画的 Pareto 前沿。**
  ——缺"去哪补"；同页 `optstack.src_hint` 的命令（tune --multi）恰好
  可指。

### R8 错误文案三要素

判据：发生了什么 / 为什么（或影响）/ 怎么办。三要素允许在**组合层**
分工：`import.fail_lead`"导入失败: "+后端详情动态拼接=合法；标题
（`common.error_title`"操作失败"）+正文+hint 行（`common.error_hint`）
三行分工=合法。**片段键单独看缺要素是设计不是缺陷，改写前先看
组合层**（消费点 grep `t("…")`）。

- 反例 `common.error_generic`：**操作未成功（服务未就绪或请求异常），
  可稍后重试**——"可稍后重试"无动作指向；两个"可能原因"是猜测不是
  事实（kit.js 该兜底只在 envelope 无 errors/error/reason 时触发，
  真实原因就是"服务端未返回原因"——写事实比写猜测好）。
- 两要素正例（可保留，补第三件即满血）`dashboard.cred_load_fail`：
  **锚注册表加载失败，可信度数字暂不可用**——缺"怎么办"（如"刷新
  重试，仍失败看服务端日志"）。

### R9 按钮动词具体化

判据：按钮=动词+宾语，宾语是真实对象（"计算""扫描""保存配方""查看
诊断"）；"一键/立即/秒懂/极速"默认不用——除非"秒级"是事实描述。

- 对照 `tune.help_channel`：**仿真通道先选 fake：秒级出结果、不占用
  软件许可**——"秒级"是 fake 通道的真实时间尺度（事实），放行。
- 反例 `detail.failure_view_btn`：**一键查看诊断**——"一键"没说哪一键、
  也不是区别性事实（页面上就一个按钮），删掉不丢信息：→"查看诊断"。

### R10 help 块先给"怎么读"再给"是什么"

判据：图表类 help 的第一句给判读法（怎么读、什么算好），不是功能
罗列。

- 正例 `gallery.cred_howto`：**怎么读这张图：每条线是同一个物理结构
  的 S 参数预测——橙线=HFSS（商业电磁仿真软件，仲裁基准），蓝线=
  openEMS（本仓主力开源引擎）。两条线越贴近，说明两个独立软件对同一
  结构给出越一致的预测……**——先给读法、再给判据。

### R16 范式正例（"页面名+动作+预期产物"三件套）

新写段落文案拿不准时，对齐仓内最优模式：

- `guide.wf1_out`：**产出：recipes/ 下一个 YAML 文件（页面顶部显示
  路径），内含参数值与优化范围（low/high）——下一步调参吃的就是这个
  文件。**——产物路径+字段+下游消费者，三件全齐。

## 四、英文侧（en 与 zh 同笔改）

### R15 en AI 味词表与同族判据

词表（出现即改）：seamlessly/seamless、empower*、leverage*、
effortless*、unlock*、robust（比喻义）、delve、comprehensive、
intuitive、streamline*、elevate、harness、supercharge、game-chang*、

## 五、流程与验收（改写时）

### R18 信息守恒验收清单（每键改完过一遍）

- [ ] 键名、`{placeholder}`、命令、路径、单位、数字、阈值逐字未动
- [ ] 原文每个信息点在改写版里找得到（含括号补充说明）
- [ ] 没有新增原文没有的事实/承诺（"预计""大约"类不许无中生有）
- [ ] zh/en 同笔改（一侧改了另一侧必须跟上，两语言同构）
- [ ] 词表值永不含 HTML（i18n.js 头注纪律；`&lt;` 字符实体除外）
- [ ] esc 体系共存纪律：t() 只产文本，动态数据照旧走 esc/escAttr
- [ ] 改后重跑 `runs/aurora_k/scan_i18n_deai.py --tables`，命中数
  只降不升

### 扫描器与守则的分工

守则=人工判据（含误杀边界，最终裁定权）；扫描器
`runs/aurora_k/scan_i18n_deai.py`=机械面（C1-C8 检查类，TSV 明细），
命中是"疑似清单"不是改写指令——C5（均值回归疑似）与 C6（对仗三连）
两类误报率最高，必须人工复核后再动。
