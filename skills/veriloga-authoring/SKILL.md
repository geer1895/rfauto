## The golden rules (each with kernel evidence)

1. **One file, complete modules.** `module name (ports);` ... `endmodule`.
   A missing `endmodule` does not abort the parse (fail-soft warning
   `unterminated_module`), but a clean parse has zero warnings — always close
   the module. Evidence: `_parse_module_body` EOF branch warns
   `unterminated_module` instead of raising.
2. **Declare ports with a direction, always.** Both styles parse: ANSI header
   `module m (input a, output b);` or 1995 header `module m (a, b);` plus body
   lines `input a;` / `output b;`. Directions from body declarations backfill
   header-only names. Evidence: `_parse_header_ports` + `_parse_direction_decl`.
   A port never given a direction anywhere simply never appears in the ports
   table (silent omission) — so write the direction.
3. **Declare every node `electrical`.** `electrical p, n;` (multi-name one
   decl is fine). Types outside the known word list (electrical/wire/wand/
   wor/tri/reg) trigger warning `unknown_net_type`. Evidence: `KNOWN_NET_TYPES`
   + `_parse_net_decl(unknown_type=True)`.
4. **Declare parameters in the module body, not the `#(...)` header.**
   `parameter real r = 1.0 from [0:inf);` lands in the param table with a
   structured range; `module m #(parameter real r = 1.0) (p, n);` is consumed
   raw and the parameter is **silently absent** from the param table (zero
   warnings — data loss). Evidence: `parse_module` discards
   `header_params_raw`; `_parse_param_decl` records body params.
5. **Analog behavior goes in `analog begin ... end`** (or one statement
   `analog V(p, n) <+ ...;`). Contribution statements are the payload:
   `V(out) <+ expr;` / `I(m) <+ expr;` / `V(p, n) <+ expr;`. The parser
   counts statements by category and normalizes each contribution RHS into a
   prefix tree — an RHS that fails normalization keeps its raw text but loses
   the tree (warning `expr_normalize_failed`), which breaks downstream
   consumers. Evidence: `_classify_simple_stmt` + `expr_to_prefix`.
6. **Stay inside the operator closed set in contribution RHS:**
   `|| && == > < >= <= + - * / % ** ?:`, unary `- !`, calls `f(a, b)`,
   access `V(x)`/`I(x)` (same shape as calls), index `a[i]`, range index
   `a[m:n]`. Bitwise `& | ^ ~ << >>` are **not** in the precedence table —
   an RHS containing them fails normalization (fail-closed by design).
   Evidence: `PRECEDENCE` dict + probe: `V(b) <+ V(a) & V(a);` → warning
   `expr_normalize_failed`, tree None.
7. **No system tasks inside expressions.** `$realtime`, `$temperature` etc.
   are lexed as `sys` tokens and rejected by the expression normalizer
   (warning `expr_normalize_failed`, RHS tree None). Evidence: `expr_to_prefix`
   raises on non-num/id/str/punct tokens.
8. **No `case`, no named blocks, no `generate`, no `analog function` bodies.**
   `case` corrupts statement attribution (its labels merge into the next
   contribution LHS and the module closure is miscounted); `begin : name`
   leaks `: name` into the next statement's LHS; `analog function` bodies are
   skipped with a warning. Use `if/else` chains and anonymous `begin/end`.
   Evidence: probe of `case (m)` → `unterminated_module` warning +
   `lhs: 'case(m) 0 : V(b)'`; named block probe → `lhs: ': blk V(b)'`;
   `_parse_analog` function branch warns `analog_function_skipped`.
9. **Attributes are written as `(* text *)` directly before `module`**
   (document-level) — they attach to that module verbatim. Evidence:
   `_consume_attributes` pending slot.
10. **Events are registered, not interpreted.** `@(initial_step)` /
    `@(cross(V(out) - v, +1))` — event name + raw args land in the events
    table and the host statement is still classified. Evidence: `_parse_event`.

## Minimal skeleton (parses clean: 0 warnings, tree non-None)

```va
// behavioral one-port, placeholder default (not a design value)
module r_branch (p, n);
  electrical p, n;
  parameter real r = 1.0 from [0:inf);
  analog begin
    V(p, n) <+ r * I(p, n);
  end
endmodule
```

## Write → parse → fix loop

After writing or editing any .va text, run the parse self-check and iterate
until the clean-parse bar is met (see `references/workflow.md`):

```python
from rfauto.service.veriloga_service import parse_veriloga_file
result = parse_veriloga_file("my_model.va")
assert result["ok"], result["errors"]
assert result["warnings"] == [], result["warnings"]
assert all(c["rhs_prefix_tree"] is not None
           for m in result["modules"].values()
           for c in m["analog"]["contributions"])
```

FAIL is reported as FAIL (rfauto rule #122): never widen the skill's claims
to make a failing parse look green — fix the .va, or record that the form is
outside the accepted subset.
