> Generated by `rfauto.service.skill_service.card_to_skill` from the

## When this skill applies

- 拓扑：均匀微带线（锚模板，WP2.1：校准件+引擎仲裁探针+数据工厂，单点秒-分钟级）
- f0：2.5 GHz ｜ 端口：2 ｜ 时长 ≤30.0 ns ｜ 网格档：0.0 mm
- 提取口径：S11/S21 @ MSLPort 1-2（均匀线：S21 相位斜率→εeff，β 金标准（#162）；|S11| 显著非零=端口/网格判废信号）
- 参数：w_mm, line_len_mm
- 基板：{"er":3.66,"h_mm":0.508}

## Workflow (typed commands; every value comes from the kernel)

```bash
rfauto syn mline <Z0_ohm> --freq <GHz> --stackup <materials.yaml key> --json
rfauto syn wilkinson --f0 <GHz> --z0 <ohm> --stackup <key> --json   # family synthesis (per-arm epsilon_eff)
```

How to read the kernel JSON envelope:

| key | meaning | act on it |
|---|---|---|
| `status` | three-state machine: ok / er_eff_fallback / needs_calibration | only ok is a design value; er_eff_fallback means epsilon_eff fell back to bulk er (lambda-based lengths are not trustworthy); needs_calibration means back-substitution missed the 0.5 ohm self-consistency band |
| `delta_z0` | back-substituted Z0 minus target | must be < 0.5 ohm for status ok |
| `er_eff_source` | provenance of epsilon_eff (ep_reff = skrf effective permittivity) | surface it verbatim; never invent an epsilon_eff |
| `width_mm` | the authoritative synthesized width for this stackup | do not copy widths from other docs or templates (single-source rule, test_width_single_source) |

## Known boundaries

- 参数语义：w_mm=线宽（Z0 由 skrf HJ 综合定：50Ω@rogers4350b=1.113mm），line_len_mm=两端口间线长
