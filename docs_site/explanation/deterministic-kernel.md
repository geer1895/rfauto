# 解释：为什么数值只在确定性内核

> 这是一篇 explanation（解释文）：回答"为什么 rfauto 立这条铁律、
> 它靠什么成立"，不教操作。操作面：docs/tutorials/mcp_in_practice.md
> （agent 接入）、docs/how-to/use-calculators.md（计算器调用）；
> 架构总览：docs/explanation/layered-architecture.md。

## 一条铁律

rfauto 从立项起就立了一条硬规则（内核立规 7，2026-09-05 LLM×EDA
调研批采纳）：**LLM/agent 永远不产生物理数字**。频率、损耗、几何尺寸、
S 参数——一切会进仿真、进报告、进器件图纸的数值，只允许出自四类
"确定性产地"：

1. **综合引擎**（闭式公式精算，如 HJ 微带线宽综合 `core/synthesis.py`）；
2. **确定性计算器**（`core/calc_families/` 注册表里的纯函数）；
3. **EM 求解器**（openEMS/HFSS/ADS/…，经适配器契约调用）；
4. **锚注册表**（`knowledge/anchors.yaml`，引擎对偏差的已仲裁校准值）。

LLM 在这条链路里的合法职责只有两件事：**编排**（决定下一步调哪个
typed tool call）与**解释**（把 JSON 结果翻译成人话）。它给出的任何
物理数字都是违规产物——不是"质量差一点"，是架构层面不允许出现。

## 为什么：三个支撑

### 1. 幻觉面：语言模型对物理量没有接地

LLM 对"2.4 GHz 微带 50Ω 线宽在 FR-4 上大概 3mm"这类问题能流利作答，
但这个答案是训练语料的插值——它不携带你手上这版板材的实际铜厚、
粗糙度、蚀刻欠量。数值一旦从语言模型流出，就没有 provenance 可查：
你无法回答"这个 3mm 是哪台机器、哪个公式、哪个版本算的"。

rfauto 的对策不是"提示词里叮嘱 LLM 算准点"，而是**让通道不存在**：
agent 工具循环（`service/agent_runtime.py`）只消费 typed tool call，
工具返回 JSON 信封；agent 想要数字，唯一的路是发起一次计算器/求解器
调用。MCP 面 157 个工具（2026-10-18 实测，`scripts/check_numbers.py`
同源）全是这种"参数进、数字出"的确定性端点。

### 2. 可复现面：模型相关的数字不可重放

同一问题问两个模型（或同一模型两次）会得到不同答案。仿真自动化的
核心资产是**可重放**：三个月后用今天的代码、今天的锚注册表重跑同一
配方，判读结论必须一致（RECAST 判据重放即为此设，见
docs/tutorials/recast-walkthrough.md）。模型插值数字破坏这一切——
它既不能重放，也不能进回归仓。确定性内核的输出则逐位稳定：core 层
纯函数零 IO、零随机性（要随机必须显式带种子），同一入参永远同一
出参，doctest 与单测直接把示例数值钉死。

### 3. 审计面：判读交给模型等于判读不可辩护

"这个结果能不能采信"是射频工程的性命攸关问题（坏数据入库比算得慢
贵得多）。rfauto 把判读全部内核化为确定性门（健康体检 G11、成本门、
互易门……），判据在真跑前预声明、跑完不修改；证据不足如实报
UNKNOWN。自治环（autotune）里的 critique/fix 同样是 service 层确定性
函数（如 `service/autotune_service.py` 的 `critique_point`）——LLM
读得懂判语，但判语不是它写的。

反面案例也来自本项目自身：**如果判读可以"商量"，就会有人（或 agent）
在 FAIL 面前忍不住改门**。项目史对这类冲动给出过明确答案（#122）：
校准目标冲突时如实记 FAIL/PARTIAL，学术诚信优先于验收表全勾；红项
永不静默隔离。判读权在内核，正因为内核不会被"说服"。

## 一个决定性实验：公式通道预筛调查（2026-09-05）

铁律不是教条，它顶住了一次严肃的挑战："既然 LLM 不能产数字，那把
教科书闭式公式写成代码当预筛器行不行？"——即 fake/公式通道能否胜任
跨保真预筛。完整证据链沉淀在 docs/fake_channel_investigation.md
（后续任何会话动 fake/预筛/跨保真 gate 前必读），结论速览：

| 实验 | 方法 | 排序一致性 ρ |
|---|---|---|
| fake 原生（修复后基线） | 解析近似 vs openEMS | 0.377 |
| 锚重推（谷位对齐） | 公式+锚校正 | 0.608 |
| E5 电路通道探针 | Pozar 偶/奇模，零拟合 | 0.183 |
| E6 fake-v2 混合 | 电路形状+物理修正三级变体 | 最好也只有 0.6 一档，一条变体 −0.278 |
| **NN 校准代理** | 0.2 增广战役 9 种子+16 LHS | **0.845 PASS** |

每条"改良公式"路径都被实测穷尽后否决。机理解释是结构性的：排序分歧
由**公式看不见的物理**（T 型结储场、臂间耦合、馈线真实阻抗、寄生）
主导——闭式谷位 2.5GHz vs 全波 2.2GHz 的 −12% 错位，恰好落在排序最
敏感的带内平坦区。最终架构分层就此定案：

```
fake（冒烟/CI/UI，秒级）
  → 校准代理（预筛，NN，LOOCV ρ=0.845）
    → openEMS（中保真精算）
      → HFSS（终验仲裁）
```

注意这条链的深层含义：**连"正确的公式"都不被信任去预测响应**。权威
公式的合法位置是综合层（线宽/臂长）、代理物理特征、锚反推——不是
响应预测。这是"数值只在确定性内核"的加强版：确定性内核内部还要再
分可信层级，每升一级都要证据。

## 高保真也不等于真理：HFSS 仲裁与锚

铁律的另一面常被误解：以为"确定性产地"产出的就是真值。不是。求解器
之间同样存在**系统性偏差**（网格方法学、边界吸收、端口定义差异），
所以 rfauto 立了第二条配套规约（2026-09-08 用户立规）：**HFSS 结果为
对齐基准**——其他引擎/设计值向 HFSS 对齐；且这条基准本身也要走仲裁
背书流程（经 HFSS 仲裁背书的引擎经验常数，如 openEMS f_dip·L≈76.8，
才可作为配方 band×bounds 设计依据）。

仲裁产出的偏差校准值不散落在代码里，而是登记进锚注册表
（`knowledge/anchors.yaml`，2026-10-23 实测 87 锚）——每个锚带完整
provenance（仲裁 run 目录、commit、被替换的旧值），运行时只读、写入
只经人工 commit。这是"数字的第四个产地"：它仍是确定性面（一个带出处的
常量），但它的可信度不来自公式，而来自**登记制度的可追溯**。详见
docs/explanation/anchor-and-verdict.md。

还有一条更深的教训（#118）：**确定性内核自身也会错**——推导和解析
期望都可能算错。所以数值算法的裁判从来不是"我自己再推一遍"，而是
"小步长收敛数值 + 独立来源解析值"双重对照，回收钉（解析恒等式
≤1e-12）只是下限守卫不是充分证明。

## 架构怎么强制（不是靠自觉）

| 机制 | 位置 | 强制力 |
|---|---|---|
| 分层约束 | import-linter 契约 | 数值代码进不了壳层——cli/mcp/ui 里出现公式即架构违例 |
| 纯函数纪律 | `core/` 全域 | 零 IO 零随机，doctest 把示例数值钉进测试门 |
| 回收钉 | core/单测 | 解析恒等式 ≤1e-12；合成已知量回收换算系数（#340 教训） |
| Agent 写面隔离 | 内核立规 6 | agent 改配方只能走沙箱草稿 → 三层 Gate promote，无直接写工具 |
| 计算器注册表 | `core/calc_families/registry.py` | 未注册函数不可达；实验键默认拒跑 |
| 公式出处注册表 | `knowledge/formula_provenance.yaml` | 卡内/文档数字必须能对回 builder 与来源 |
| 合流预检 | `scripts/merge_preflight.py` | 计数锚/再生差异漂移在合流前拦截 |

这些机制共同保证：即使某个贡献者（或某个 agent 会话）想在壳层里塞
一个"大概 3mm"，测试门会在合流前红掉，而不是等产品烧板子那天。

## 给使用者的推论

- 问 agent "这个结构谐振频率是多少"，它应该发起一次综合/计算器/求解
  调用并转述 JSON——**直接报数字的 agent 回答在 rfauto 语境里是错的**，
  哪怕数字碰巧对；
- 看到 `rfauto calc run <键>` 与 MCP 工具的输出，可以放心引用——它们
  与 README/docs_site 数字同一条 check_numbers 单源链；
- 判语（verdict/PASS/FAIL/UNKNOWN）同样不可协商：想改判据，走预声明
  流程改判据书，然后让门重新判——不是让门"这次通融"；
- 想给内核加数字产地（新计算器/新锚），走注册表+五钉清单：
  docs/how-to/add-new-calc-key.md。
